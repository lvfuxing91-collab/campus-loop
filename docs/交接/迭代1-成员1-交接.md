## 三、接口与数据约定

1. ItemRepository.search已经转义%、_和反斜杠，调用方不再重复转义。
2. ItemService.search未指定状态时默认ON_SALE；Repository本身只使用收到的条件。
3. categoryName和ownerNickname由物品联结查询取得，不是items表中的附加列。
4. detail会增加浏览量，不用于无副作用的表格预览。
5. 成色枚举为LIKE_NEW，热度排序为POPULAR，查询建造者为ItemQuery.Builder。
6. 本次文档整理不改变Java签名或数据库结构；后续签名变更登记到接口契约。

## 四、使用注意

- DatabaseManager单例在一个JVM中绑定一个数据库路径；独立数据库测试使用独立进程或统一测试库。
- PRAGMA设置按Connection生效；先调用execute关闭外键，不会影响下一次execute新开的连接。
- 现有AbstractJdbcDao方法独立开连接，不能仅在外层套inTransaction就认定跨仓储调用具有原子性。
- 时间统一使用DateTimes；布尔按0/1读写。BigDecimal写入REAL会转为浮点数，精度测试需覆盖实际金额边界。
- 当前基础统计的12.0 kg按全部种子物品系数估算，成交口径在接入流转后统一。

## 五、验证步骤

在项目根目录、已配置可用JDK的终端执行：

```bash
./mvnw -B -ntp -pl campus-core,campus-dao -am test
```

预期：core 21项、dao 7项通过，无失败、错误和跳过。

```bash
./mvnw -B -ntp clean package
```

预期：全项目34项测试通过并生成campus-app/target/campus-loop.jar。

使用全新验收目录启动，保留原data/campus.db：

```bash
java -Dfile.encoding=UTF-8 -Dcampusloop.db=target/member1-check/campus.db -Dcampusloop.home=target/member1-check -jar campus-app/target/campus-loop.jar
```

验收点：admin / Admin@123可登录；物品列表3条；统计用户3、物品3、在售3；linxiaolv / Student@123的“我的发布”为2件。数据库创建在指定验收目录，关闭程序后再次打开检查数据持久化。
