## 一、用户、物品实体与业务模块

系统将用户、物品、流转和评价抽象为实体类，由业务服务处理注册、发布、交易、评价与统计规则。实体和服务接口位于 `campus-core`，业务实现位于 `campus-service`。

### 1. 用户实体与账号业务

[User.java](../../campus-core/src/main/java/edu/campusloop/core/model/User.java) 保存用户身份和账号信息。

| 字段 | 含义 |
|---|---|
| `id` | 用户编号 |
| `username`、`nickname` | 登录名和显示昵称 |
| `passwordHash`、`salt` | 密码摘要和盐值 |
| `role` | 学生或管理员角色 |
| `creditScore` | 用户信用分 |
| `enabled` | 账号是否启用 |
| `createdAt` | 注册时间 |

[AuthServiceImpl.java](../../campus-service/src/main/java/edu/campusloop/service/AuthServiceImpl.java) 实现注册、登录和修改密码：注册时校验输入并检查用户名是否重复；登录时查询用户、检查启用状态并验证密码；修改密码时校验原密码后更新密码摘要。

### 2. 物品实体与管理业务

[Item.java](../../campus-core/src/main/java/edu/campusloop/core/model/Item.java) 描述校园闲置物品。

| 字段 | 含义 |
|---|---|
| `id`、`ownerId`、`categoryId` | 物品编号、发布者和分类 |
| `title`、`description` | 物品名称和描述 |
| `condition`、`tradeType`、`price` | 成色、交易方式和价格 |
| `status` | 在售、预订、已完成或已下架 |
| `tags`、`imagePath` | 标签和图片路径 |
| `viewCount`、`createdAt`、`updatedAt` | 浏览次数、创建时间和更新时间 |

[ItemServiceImpl.java](../../campus-service/src/main/java/edu/campusloop/service/ItemServiceImpl.java) 处理发布、修改、下架、详情、检索和收藏。发布时校验标题、描述、价格与分类；修改和下架时校验操作者及物品状态；赠送和交换物品的价格统一为 0。检索支持组合条件和排序，详情访问会更新浏览次数。

### 3. 流转、评价与统计业务

| 模块 | 主要对象与实现 | 功能与规则 |
|---|---|---|
| 流转 | [Deal.java](../../campus-core/src/main/java/edu/campusloop/core/model/Deal.java)、[DealServiceImpl.java](../../campus-service/src/main/java/edu/campusloop/service/DealServiceImpl.java) | 买家发起意向；卖家接受或拒绝；完成或取消后保存状态。不能对自己的物品发起意向 |
| 评价 | [Review.java](../../campus-core/src/main/java/edu/campusloop/core/model/Review.java)、[ReviewServiceImpl.java](../../campus-service/src/main/java/edu/campusloop/service/ReviewServiceImpl.java) | 已完成流转的双方可以评价，评分 1～5；同一人对同一流转只能评价一次 |
| 信用 | `User.creditScore`、`ReviewServiceImpl` | 根据用户收到的平均星级乘以 20 更新信用分 |
| 统计 | [StatsReport.java](../../campus-core/src/main/java/edu/campusloop/core/model/StatsReport.java)、[StatsServiceImpl.java](../../campus-service/src/main/java/edu/campusloop/service/StatsServiceImpl.java) | 汇总用户、物品和流转数据；按已完成流转物品估算减排，并支持 CSV 导出 |

流转的主要状态为 `PENDING`（待确认）、`ACCEPTED`（已接受）、`COMPLETED`（已完成）、`REJECTED`（已拒绝）和 `CANCELLED`（已取消）。接受意向后物品进入预订状态，确认完成后流转和物品均进入完成状态。

## 二、数据库访问层

### 1. 数据访问层结构

```text
Swing 界面（campus-ui）
        ↓
业务服务 Service（campus-service）
        ↓ 调用
Repository 仓储接口（campus-core）
        ↓ 实现
RepositoryImpl 数据访问类（campus-dao）
        ↓ JDBC
SQLite 数据库
```

业务服务依赖仓储接口，不直接编写 JDBC 代码；具体仓储负责 SQL、参数绑定与对象映射。[Bootstrap.java](../../campus-app/src/main/java/edu/campusloop/app/Bootstrap.java) 负责创建并装配数据层和业务层对象。

### 2. 数据库连接与初始化

| 组件 | 主要作用 |
|---|---|
| [DatabaseManager.java](../../campus-dao/src/main/java/edu/campusloop/dao/db/DatabaseManager.java) | 管理数据库文件位置、建立 JDBC 连接、开启外键并提供事务入口 |
| [SchemaInitializer.java](../../campus-dao/src/main/java/edu/campusloop/dao/db/SchemaInitializer.java) | 执行建表脚本和演示数据脚本 |
| [schema.sql](../../campus-dao/src/main/resources/db/schema.sql) | 创建数据表、约束和索引 |
| [seed.sql](../../campus-dao/src/main/resources/db/seed.sql) | 写入演示用户、分类、减排系数和物品 |

系统默认使用 `data/campus.db`。建表和种子脚本使用 `CREATE TABLE IF NOT EXISTS` 与 `INSERT OR IGNORE`，使现有初始化内容可以重复执行。

### 3. 仓储接口及实现

| 数据对象 | 仓储接口 | 主要数据操作 |
|---|---|---|
| 用户 | [UserRepository](../../campus-core/src/main/java/edu/campusloop/core/repository/UserRepository.java) | 按编号和用户名查询、插入、更新、用户计数 |
| 物品 | [ItemRepository](../../campus-core/src/main/java/edu/campusloop/core/repository/ItemRepository.java) | 插入、修改、按条件检索、更新状态和浏览量 |
| 流转 | [DealRepository](../../campus-core/src/main/java/edu/campusloop/core/repository/DealRepository.java) | 插入、更新、按用户或物品查询、统计已完成流转 |
| 评价 | [ReviewRepository](../../campus-core/src/main/java/edu/campusloop/core/repository/ReviewRepository.java) | 插入评价、查询评价、判断是否已评价、计算平均评分 |
| 收藏、分类、日志及减排系数 | 相关 Repository 接口 | 提供收藏增删、分类维护、日志记录和减排系数查询 |

例如，[DealRepositoryImpl.java](../../campus-dao/src/main/java/edu/campusloop/dao/repository/DealRepositoryImpl.java) 实现流转记录存取；[ReviewRepositoryImpl.java](../../campus-dao/src/main/java/edu/campusloop/dao/repository/ReviewRepositoryImpl.java) 实现评价存取。[DealMapper.java](../../campus-dao/src/main/java/edu/campusloop/dao/repository/DealMapper.java) 通过查询关联物品和用户表，补充物品名称及买卖双方昵称。

[AbstractJdbcDao.java](../../campus-dao/src/main/java/edu/campusloop/dao/repository/AbstractJdbcDao.java) 封装 JDBC 公共操作，包括获取连接、准备 SQL、绑定参数、读取结果和释放资源。查询使用参数化语句，避免把用户输入直接拼接成 SQL。

### 4. 事务与异常处理

完成流转需要更新流转记录与物品状态，评价后需要保存评价并更新用户信用。相关写入应在同一事务中提交，以避免只完成一部分操作。

[DatabaseManager.inTransaction](../../campus-dao/src/main/java/edu/campusloop/dao/db/DatabaseManager.java) 提供事务入口：

```text
开始事务，关闭自动提交
    ↓
执行业务中的多个仓储操作
    ↓
全部成功 → commit
发生异常 → rollback
```

事务内，当前线程的仓储调用复用绑定的数据库连接；事务外调用各自获取并关闭连接。业务层通过 [TransactionRunner.java](../../campus-service/src/main/java/edu/campusloop/service/TransactionRunner.java) 声明事务边界。

数据访问异常由 [SqlErrors.java](../../campus-dao/src/main/java/edu/campusloop/dao/db/SqlErrors.java) 按约束类型转换为中文提示，原始异常和诊断细节供日志排查。

## 三、JUnit 单元测试用例

### 1. 测试环境与执行方式

项目使用 JUnit 4。工具类测试位于 `campus-core`，数据层测试位于 `campus-dao`，业务和集成测试位于 `campus-service`。

在项目根目录执行全部测试：

```bash
./mvnw -B -ntp test
```

执行完整构建和测试：

```bash
./mvnw -B -ntp clean package
```

Windows 命令行或 PowerShell 可使用 `mvnw.cmd` 执行相同参数。构建需要可用的 JDK。

### 2. 主要测试用例

| 测试类与用例 | 测试场景 | 预期结果 |
|---|---|---|
| [AuthServiceTest](../../campus-service/src/test/java/edu/campusloop/service/AuthServiceTest.java) | 注册、登录、错误密码、停用账号 | 合法用户可以登录；错误密码或停用账号被拒绝 |
| [ItemServiceTest](../../campus-service/src/test/java/edu/campusloop/service/ItemServiceTest.java) | 发布、修改、权限和交易方式 | 物品字段按业务规则设置；赠送或交换时价格为 0；越权修改被拒绝 |
| [DealServiceTest](../../campus-service/src/test/java/edu/campusloop/service/DealServiceTest.java) | 发起、接受、完成、拒绝和取消 | 合法状态迁移成功，非法操作被拒绝 |
| [ReviewServiceTest](../../campus-service/src/test/java/edu/campusloop/service/ReviewServiceTest.java) | 成交评价、重复评价和信用更新 | 重复评价或不符合条件的评价被拒绝；合法评价更新信用 |

## 四、基础数据存取

### 1. 数据库表与初始化数据

| 数据表 | 保存内容 |
|---|---|
| `users` | 用户名、密码摘要、角色、信用分和账号状态 |
| `categories` | 物品分类、排序和启用状态 |
| `items` | 发布者、物品信息、价格和状态 |
| `favorites` | 用户与物品的收藏关系 |
| `deals` | 流转物品、买卖双方、留言和状态 |
| `reviews` | 流转评价、评分和评论 |
| `operation_logs` | 关键操作的用户、动作、详情和时间 |
| `carbon_factors` | 每个分类对应的减排估算系数 |

演示数据包含 3 个用户、5 个分类、5 条减排系数和 3 件物品。表字段、关系和索引的完整说明见[数据库设计](../设计/数据库设计.md)。

**约束示例：**

- `users.username` 唯一，防止重复用户名；
- `favorites` 以 `(user_id, item_id)` 为联合主键，防止重复收藏；
- `reviews` 对 `(deal_id, reviewer_id)` 设置唯一约束，并用 `CHECK` 限制评分范围；
- 物品、流转和评价等记录通过外键关联对应用户和业务数据。

### 2. 用户和物品存取流程

**用户注册：**

```text
输入用户名、密码和昵称
    ↓
AuthServiceImpl 校验输入并检查用户名
    ↓
生成盐值和密码摘要，构造 User
    ↓
UserRepository.insert(user)
    ↓
JDBC 将用户记录写入 SQLite 的 users 表
```

**发布与查询物品：**

```text
填写物品信息并提交
    ↓
ItemServiceImpl 校验发布者、字段与分类
    ↓
ItemRepository.insert(item)
    ↓
JDBC 将物品写入 SQLite 的 items 表
    ↓
调用 ItemRepository.findById / search / findByOwner 读取并展示
```

[CampusDatabaseTest.insertAndReloadItem](../../campus-dao/src/test/java/edu/campusloop/dao/CampusDatabaseTest.java) 验证了插入物品后按 ID 回读，并核对名称、分类名称与价格。

### 3. 数据持久化与事务验证

数据库使用本地文件保存数据，系统重启后仍可读取已提交的数据。演示时可使用独立数据库路径，避免影响已有演示数据：

```bash
java -Dfile.encoding=UTF-8 -Dcampusloop.db=target/iter2-demo/campus.db -Dcampusloop.home=target/iter2-demo -jar campus-app/target/campus-loop.jar
```

以交易数据为例：先插入流转记录，再查询流转编号、物品、买卖双方及状态；确认完成后，流转和物品状态应保持一致。业务层的 [ServiceFlowIntegrationTest](../../campus-service/src/test/java/edu/campusloop/service/ServiceFlowIntegrationTest.java) 使用真实 SQLite 数据库验证了发布物品、完成流转、评价、信用分和统计数据。

数据层事务测试包括：

- `transactionCommitsWritesFromMultipleRepositories`：事务内多个仓储操作成功后，记录均可查询；
- `transactionRollsBackWritesFromMultipleRepositories`：事务内写入后抛出异常，前面的仓储写入不会保留。

上述用例位于 [CampusDatabaseTest.java](../../campus-dao/src/test/java/edu/campusloop/dao/CampusDatabaseTest.java)。
