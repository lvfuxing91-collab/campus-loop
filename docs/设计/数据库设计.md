# 数据库设计

## 一、总体说明

| 项 | 内容 |
|---|---|
| 数据库 | SQLite 3 |
| 驱动 | `org.xerial:sqlite-jdbc:3.45.3.0`（内含各平台原生库） |
| 文件位置 | 默认 `data/campus.db`，由 `AppConfig` 提供，可通过 `-Dcampusloop.db` 覆盖 |
| 建库方式 | 首次启动时 `SchemaInitializer` 执行 `db/schema.sql` 与 `db/seed.sql` |
| 时间存储 | `TEXT`，格式 `yyyy-MM-dd HH:mm:ss`，由 `DateTimes` 统一格式化 |
| 布尔存储 | `INTEGER`，0/1 |
| 连接参数 | `PRAGMA foreign_keys = ON`、`journal_mode = WAL` |

脚本位置：

- `campus-dao/src/main/resources/db/schema.sql`
- `campus-dao/src/main/resources/db/seed.sql`

## 二、ER 关系

```
users 1 ────< items >──── 1 categories 1 ── 1 carbon_factors
  │              │  │
  │              │  └────< favorites >──── users
  │              │
  │              └────< deals >──── users (buyer / seller)
  │                      │
  │                      └────< reviews >──── users (reviewer / reviewee)
  │
  └────< operation_logs
```

关系说明：

- 一个用户可发布多件物品；一件物品属于一个分类
- 用户与物品之间是多对多收藏，`favorites` 用联合主键去重
- 一件物品可产生多条流转记录（多条意向，最终只有一条成交）
- 每条已完成的流转最多产生两条评价（买卖各一）
- 每个分类可配置一条碳减排系数

## 三、表设计

### 3.1 users —— 用户

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTOINCREMENT | 主键 |
| username | TEXT | NOT NULL, UNIQUE | 登录名，3~20 位 |
| password_hash | TEXT | NOT NULL | SHA-256(盐 + 明文) 的十六进制 |
| salt | TEXT | NOT NULL | 16 字节随机盐的十六进制，每用户独立 |
| nickname | TEXT | NOT NULL | 展示名 |
| role | TEXT | NOT NULL, DEFAULT 'STUDENT' | `STUDENT` / `ADMIN` |
| credit_score | REAL | NOT NULL, DEFAULT 100.0 | 信用分 |
| enabled | INTEGER | NOT NULL, DEFAULT 1 | 1 正常，0 停用 |
| created_at | TEXT | NOT NULL | 注册时间 |

索引：`username` 唯一索引（由 UNIQUE 约束自动创建）。

### 3.2 categories —— 分类

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 主键 |
| name | TEXT | NOT NULL, UNIQUE | 分类名，管理员可维护 |
| parent_id | INTEGER | REFERENCES categories(id) ON DELETE SET NULL | 预留二级分类 |
| sort_order | INTEGER | NOT NULL, DEFAULT 0 | 展示顺序 |
| enabled | INTEGER | NOT NULL, DEFAULT 1 | 停用后不再出现在发布下拉框 |

### 3.3 items —— 物品

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 主键 |
| owner_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 发布者 |
| category_id | INTEGER | NOT NULL, FK categories(id) | 分类 |
| title | TEXT | NOT NULL | 名称，1~50 字 |
| description | TEXT | NOT NULL | 描述 |
| condition_level | TEXT | NOT NULL, DEFAULT 'GOOD' | 成色 |
| trade_type | TEXT | NOT NULL, DEFAULT 'SELL' | `SELL` / `FREE` / `EXCHANGE` |
| price | REAL | NOT NULL, DEFAULT 0 | 价格，出售时 ≥ 0，赠送/交换为 0 |
| status | TEXT | NOT NULL, DEFAULT 'ON_SALE' | `ON_SALE` / `RESERVED` / `COMPLETED` / `OFF_SHELF` |
| tags | TEXT | NOT NULL, DEFAULT '' | 标签，逗号分隔 |
| image_path | TEXT | 可空 | 图片相对路径（迭代 3 启用） |
| view_count | INTEGER | NOT NULL, DEFAULT 0 | 浏览计数 |
| created_at | TEXT | NOT NULL | 发布时间 |
| updated_at | TEXT | NOT NULL | 最后修改时间 |

索引：

| 索引 | 列 | 用途 |
|---|---|---|
| `idx_items_owner` | owner_id | "我的发布" |
| `idx_items_category` | category_id | 分类筛选与分类统计 |
| `idx_items_status` | status | 只查在售物品 |
| `idx_items_created` | created_at DESC | 最新发布排序 |

### 3.4 favorites —— 收藏

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| user_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 收藏人 |
| item_id | INTEGER | NOT NULL, FK items(id) ON DELETE CASCADE | 被收藏物品 |
| created_at | TEXT | NOT NULL | 收藏时间 |

主键：`(user_id, item_id)`，天然保证不重复收藏。

### 3.5 deals —— 流转记录

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 主键 |
| item_id | INTEGER | NOT NULL, FK items(id) ON DELETE CASCADE | 物品 |
| buyer_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 买家 |
| seller_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 卖家 |
| type | TEXT | NOT NULL | 与物品交易方式一致：`SELL` / `FREE` / `EXCHANGE` |
| message | TEXT | 可空 | 意向留言 |
| status | TEXT | NOT NULL, DEFAULT 'PENDING' | `PENDING` / `ACCEPTED` / `COMPLETED` / `CANCELLED` / `REJECTED` |
| created_at | TEXT | NOT NULL | 发起时间 |
| updated_at | TEXT | NOT NULL | 状态变更时间 |
| completed_at | TEXT | 可空 | 完成时间 |

索引：`idx_deals_buyer`、`idx_deals_seller`、`idx_deals_item`。

### 3.6 reviews —— 评价

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 主键 |
| deal_id | INTEGER | NOT NULL, FK deals(id) ON DELETE CASCADE | 对应流转 |
| reviewer_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 评价人 |
| reviewee_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 被评价人 |
| rating | INTEGER | NOT NULL, CHECK (1..5) | 星级 |
| comment | TEXT | 可空 | 评论 |
| created_at | TEXT | NOT NULL | 评价时间 |

约束：`UNIQUE (deal_id, reviewer_id)` —— 一次流转中每人只能评一次；`CHECK` 保证星级在 1~5。

### 3.7 operation_logs —— 操作日志

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 主键 |
| user_id | INTEGER | NOT NULL, FK users(id) ON DELETE CASCADE | 操作人 |
| action | TEXT | NOT NULL | 动作码，如 `LOGIN`、`PUBLISH_ITEM` |
| detail | TEXT | 可空 | 详情 |
| created_at | TEXT | NOT NULL | 时间 |

索引：`idx_logs_created`（按时间倒序查最近操作）。

### 3.8 carbon_factors —— 碳减排系数

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| category_id | INTEGER | PK, FK categories(id) ON DELETE CASCADE | 分类 |
| kg_co2_saved | REAL | NOT NULL, DEFAULT 0 | 每件物品再利用估算的减排量（kg CO₂） |

## 五、事务与一致性

| 场景 | 事务边界 |
|---|---|
| 发布物品 + 写操作日志 | 同一事务，任一失败整体回滚 |
| 完成流转（改物品状态 + 改流转状态 + 写日志） | 同一事务 |
| 注册用户（插入用户 + 写日志） | 同一事务 |
| 统计查询 | 只读，不加事务 |

实现方式：`DatabaseManager.inTransaction(work)` 接受一个回调，内部 `setAutoCommit(false)` → 执行 → `commit`，异常时 `rollback` 并包装为 `DataAccessException`。

## 六、初始化与重建

`SchemaInitializer.initialize(database)`：

1. 设置 `PRAGMA foreign_keys = ON`、`journal_mode = WAL`
2. 依次执行 `schema.sql`、`seed.sql`（均使用 `CREATE TABLE IF NOT EXISTS` 与 `INSERT OR IGNORE`）
3. 记录日志

因此删除 `data/campus.db` 后重启，系统会自动重建结构并恢复演示数据，这一点在交接单的验证步骤中被反复使用。
