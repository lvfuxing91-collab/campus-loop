## 一、契约范围

冻结内容：`edu.campusloop.core` 下的实体字段、枚举取值、仓储接口、服务接口。实现类可以自由重构，但不得改变这些签名。

## 二、枚举

| 枚举 | 取值 | 说明 |
|---|---|---|
| `Role` | `STUDENT`、`ADMIN` | 用户角色 |
| `ItemStatus` | `ON_SALE`、`RESERVED`、`COMPLETED`、`OFF_SHELF` | 物品状态 |
| `TradeType` | `SELL`、`FREE`、`EXCHANGE` | 交易方式 |
| `DealStatus` | `PENDING`、`ACCEPTED`、`COMPLETED`、`CANCELLED`、`REJECTED` | 流转状态 |
| `ItemCondition` | `NEW`、`LIKE_NEW`、`GOOD`、`FAIR` | 成色 |
| `ItemSortType` | `LATEST`、`PRICE_ASC`、`PRICE_DESC`、`POPULAR` | 排序方式 |

所有枚举提供 `getDisplayName()` 与中文 `toString()`，界面直接展示中文，数据库存枚举名。

## 三、实体

| 类 | 关键字段 | 设计约束与用途 |
|---|---|---|
| `User` | id, username, passwordHash, salt, nickname, role, creditScore, enabled, createdAt | `username` 非空且唯一；`creditScore` 初始 100 |
| `Item` | id, ownerId, categoryId, title, description, condition, tradeType, price, status, tags, imagePath, viewCount, createdAt, updatedAt, categoryName, ownerNickname | `price` ≥ 0；`FREE`/`EXCHANGE` 时价格为 0；`categoryName`/`ownerNickname` 为查询补充字段 |
| `Category` | id, name, parentId, sortOrder, enabled | `name` 非空且唯一 |
| `Favorite` | userId, itemId, createdAt | 联合唯一 |
| `Deal` | id, itemId, itemTitle, buyerId, buyerNickname, sellerId, sellerNickname, type, message, status, createdAt, updatedAt, completedAt | `buyerId != sellerId` |
| `Review` | id, dealId, reviewerId, reviewerNickname, revieweeId, rating, comment, createdAt | `rating ∈ [1,5]`；同一 `(dealId, reviewerId)` 唯一 |
| `OperationLog` | id, userId, username, action, detail, createdAt | `action` 保存中文操作名称，username由查询补充 |
| `CarbonFactor` | categoryId, categoryName, kgCo2SavedPerItem | 每件物品的分类减排系数 |
| `StatsReport` | totalUsers, totalItems, onSaleItems, totalDeals, completedDeals, carbonSavedKg, itemsByCategory | 可变汇总DTO，不单独建表 |

## 六、查询对象

`ItemQuery` 使用ItemQuery.Builder构造，支持关键词、分类、价格、交易方式、状态、所属人、排序和分页：

```java
ItemQuery query = ItemQuery.builder()
        .keyword("键盘")          // 匹配标题、描述、标签
        .categoryId(2L)           // 分类过滤
        .priceRange(new BigDecimal("0"), new BigDecimal("100"))
        .status(ItemStatus.ON_SALE)
        .sort(ItemSortType.PRICE_DESC)
        .page(1).pageSize(20)
        .build();
```

语义约定：

- 未设置的字段不参与过滤
- `keyword` 为空白串时视为未设置
- `keyword` 中的 `%`、`_` 按字面匹配（SQL 使用 `ESCAPE '\'`）
- 默认排序为LATEST，默认第1页、每页20条；pageSize限制1~200。
- 价格边界反向时交换上下限。
- ItemService.search默认追加ON_SALE，Repository.search不自行追加状态。
- ItemService.detail增加浏览量。

## 七、错误契约

| 场景 | 抛出 | 调用方处理 |
|---|---|---|
| 输入格式非法 | `ValidationException` | 界面直接展示 message |
| 登录失败 / 账号停用 | `AuthenticationException` | 统一提示"用户名或密码错误"；停用单独提示 |
| 违反业务规则（重复用户名、非法状态跳转、越权操作） | `BusinessRuleException` | 展示 message |
| SQL 执行失败 | `DataAccessException` | 记录内部细节；数据库提示统一脱敏列为界面改进项 |
| 目标不存在 | `BusinessRuleException`（message 含"不存在"） | 提示并刷新列表 |

DAO当前message可能包含SQL；界面由UiUtils.showError处理RuntimeException，错误展示的目标是简洁中文提示。DatabaseManager.inTransaction回调中的RuntimeException回滚后原样抛出，其他Exception回滚后包装为DataAccessException。

事务约定：`DatabaseManager.inTransaction`把连接绑定到当前线程，`AbstractJdbcDao`的所有公共方法通过`withConnection`取得该连接，因此同一事务内多个仓储的写入共用一次提交或回滚。事务外调用仍各自新开连接并在结束后关闭，调用方无需感知。嵌套调用复用最外层事务，由最外层统一提交。
